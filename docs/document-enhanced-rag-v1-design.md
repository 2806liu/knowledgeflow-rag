# 文档增强问答与多轮理解设计 v1

日期：2026-10-15
状态：用户已确认实施；功能代码与自动回归已完成，真实模型与浏览器验收结果以 evaluation/results/document-enhanced-v1 下的报告为准。
项目：仅RAG项目；与Agent项目隔离。

## 1. 已确认范围

1. 本轮完成文档增强回答、LLM问题解析、会话焦点延续和必要的受限补检索。
2. 无附件时允许明确的通用知识问题，由当前LLM回答并标记模型知识。
3. 文档概述、指定文档事实始终依据原文；解释与比较可补充用户所问的通用知识。
4. 日常工作台默认document_enhanced；保留document_strict模式和原有严格回归。
5. 不开启联网搜索、不启用新的Dense/Qdrant链路，不修正长文概述240秒期限问题。
6. 模型补充不得宣称是论文内容，不得挂靠文档引用，不作为后续轮次的已核验文档事实。

## 2. 数据流

问题 + 范围/策略快照
→ MemoryManager读取近期轮次、实质回答、讨论焦点、待澄清候选
→ QueryResolver：增强路径以LLM做结构化解析，规则做确定映射及范围校验
→ AnswerPolicy确定各回答方面的证据与知识补充权限
  - overview：现有OverviewService，只用原文
  - document_fact：文档证据不足时说明不能确认
  - concept/comparison/general：允许标注的模型知识
→ 现有BM25/原引用重取证/相邻证据
→ 生成器决定输出，或请求一次定向补检索
→ 补检索后最终生成，不能继续循环
→ 来源结构校验与前端分区
→ 回答、来源类型、焦点变更、澄清状态和run记录原子保存

真正通用问题且无资料时可跳过检索；无对象的“这篇讲什么”必须澄清。
解析失败、服务故障、空检索、资料未就绪分别记录，不能统一伪装为资料不足。

## 3. 模块职责

### 3.1 QueryResolver：问题语义解析

输入：当前问题、限定范围、活动文档、近期完整轮次、最近实质回答及条目、pending_reference、带来源类别的摘要。
输出使用Pydantic严格模型：
- intent：overview/document_fact/concept_explanation/comparison/general_question/clarification。
- resolved_query：保留用户原意的独立问题。
- requested_aspects：用户要求的原理/用途/局限等方面，不主动无限扩展。
- referenced_turn_id、referenced_unit_ids、candidate_keys。
- document_ids：必须是本轮允许范围的子集。
- clarification_question、解析方法与调用诊断。

增强模式不在LLM解析前仅因无文档、最近回答是拒答而提前终止。
精确选择候选等可用确定规则处理；重复“第二点”存在真实歧义时展示候选，不要求LLM猜。
LLM返回的文档ID、轮次、条目必须真实存在并属于当前会话；自报置信度不当作事实准确率。
鉴权/超时/无效结构需明确诊断；有确定规则可安全回退，其余不能凭空解释用户指代。

### 3.2 MemoryManager + ConversationService：焦点与待澄清状态

职责分离：ConversationService拥有附件、策略、dialogue_state的事务持久化；MemoryManager组装记忆并提出焦点更新。
conversations.payload新增dialogue_state；conversation_memory继续存滚动摘要，后台摘要不得覆盖前台焦点。

dialogue_state字段：
- current_topic及topic_source_type。
- last_substantive_turn_id。
- active_reference：历史轮次、条目及其有效文档来源。
- pending_reference：被追问的轮次、候选条目/标题/文档、范围版本。
- 用户纠正及明确终止澄清的状态。

有效回答和有实质内容的部分回答可更新讨论焦点。
拒答、错误、澄清不覆盖最近实质回答；澄清会单独更新pending_reference。
用户只回复“目标与范围”时优先尝试接续候选，候选不唯一时继续澄清。
用户换主题、取消澄清或改变范围后，旧候选需要校验/清理。
上传文档B后“这篇”按已确认规则指B；明确引用历史回答时另行核验其文档是否仍在本轮范围。
模型知识条目也可继续追问，但来源类型保留model_knowledge，不能生成文档chunk。
旧会话缺少字段时，从有效历史推导，避免要求用户重新上传或清空历史。

### 3.3 AnswerPolicy：来源权限与模式

权限由代码落实，不由LLM自由扩大：
- document_strict：只能依据当前文档证据；无据拒答。
- document_enhanced：概念、解释、比较可用模型知识；概述及论文具体事实仍要求文档。
- 混合问题按方面判断。例如“论文实验参数是什么，并解释参数作用”：参数值必须有文档依据；一般作用可标记为模型补充。
- 补充只响应用户所问方面，不自动增加大量背景。
- 未查到、解析失败、检索异常不能证明全文不存在。
- 模型知识是模型既有知识，不自动联网、不声称最新或已验证。

工作台默认增强并提供模式切换；影响后续轮次，不修改历史回答标签。
新请求可显式传answer_policy。旧API调用省略时保持严格行为，避免旧客户端和评测悄悄改变。
每轮冻结effective_policy并记录幂等关系；模型知识回答不得在严格模式中当作证据复用。

### 3.4 EnhancedAnswerService：增强生成与受限补检索

复用当前LLM客户端、ContextBuilder、BM25、ReferenceEvidenceLoader和EvidenceExpander。
不启用新向量库或Embedding服务。

通常先解析一次，再生成一次。
生成器可输出action=retrieve_more及一个缺失方面的查询，此时不发布中间答案。
最多再检索一次，然后最终生成；再次请求检索视为预算终止并明确未解决部分。
必要原引用优先，所有补充仍限定本轮文档范围、片段数与输入预算。

独立结构化返回，不放宽原严格答案校验器：
- answer_status：answered/partial_answer/insufficient_evidence/clarification。
- answer_basis：document_only/document_and_model/model_only/none，由校验后的正文区块计算。
- sections：source_type、content、citation_numbers。
- unresolved_aspects：尚不能回答的文档事实。
- cited_numbers：仅真实使用的文档编号。

document区块的引用校验对应当前规范片段；model_knowledge区块不得附文档引用。
若所有指定文档事实均缺失且无可回答部分，则insufficient_evidence。
若通用问题由模型知识回答，则answered+model_only+citations=[]。
若能解释概念但缺少用户要求的论文参数，则partial_answer并列出缺失方面。

### 3.5 响应契约与前端来源展示

涉及schemas.py、conversational_flow.py、app/static/app.js及必要样式。
保留answer字符串、citations和旧字段；新增answer_policy、answer_basis、answer_sections和unresolved_aspects。
answer字符串由服务端已校验区块组装，避免正文与来源区块不一致。
混合回答显示“文档依据”“通用知识补充”；纯模型显示“模型通用知识”，不能显示为“知识库有据回答”。
来源面板只列文档引用；无附件通用问答没有伪造引用。
历史条目、摘要和后续问题解析都保留区块来源类型。
编号存在、JSON合法只证明结构，不宣称语义真实性。

### 3.6 回归与观测

保存：原问题、解析结果、焦点前后、候选选择、策略快照、检索/补检索、原文锚点、各阶段模型调用和预算、来源区块、失败原因。
不记录密钥；真实回答日志仅留项目A忽略目录。
旧严格评测与增强评测分开统计，不能把模型补充无引用当作原严格评测通过。
语义初审与人工确认绑定实际报告哈希，保留支持原文及模型知识正确性判定。

## 4. 故障和预算

- 普通增强问答最多3次前台逻辑生成：解析1次，答案/补检索决策1次，补检索后的最终生成至多1次。
- 结构化生成首次不合规时，若仍有调用额度，可用第3次重新生成；修复为最终尝试且不再补检索，仍不放宽校验。
- 通常为2次；后台滚动摘要另计，沿用自己的有限预算。
- 每次实际HTTP重试受现有有限重试配置与剩余总时间约束；另记录真实尝试数。
- 新增强问答总期限建议默认120秒，解析子阶段建议20秒，均可配置。
- 概述沿用现有独立预算/期限，不受这次普通问答新默认影响。
- 所有模型阶段包含系统提示、问题、历史、摘要、证据和输出预留；计数方法与实际usage分开记录。
- 对象歧义必须澄清；模型故障返回明确错误并保留焦点，不把故障说成用户问题不明确。
- 文档取证故障时，本轮返回错误/恢复入口；不静默降级为“已成功核验文档”的回答。
- 重复请求不能重复写消息、重复更新焦点或重复计入成功回答。

## 5. 计划测试与门槛

以下是最初计划的48项基础场景；实施中另加真实失败边界回归。验收目标不等于实测结果。

| 组别 | 场景数 | 重点 |
|---|---:|---|
| 问题解析 | 8 | 概述、事实、解释、比较、通用、混合、范围伪造、解析错误 |
| 焦点与澄清 | 10 | 拒答后追问、澄清后补标题、多组编号、用户纠正、刷新恢复、文件切换、删除和跨会话 |
| 策略 | 8 | 两模式、有/无文档、概述原文约束、具体事实、混合方面、旧API默认 |
| 增强生成 | 8 | 文档足够、只有名称、缺少局限、纯模型、参数缺失、部分回答、补检索、补检索上限 |
| 来源/接口/前端 | 8 | 伪造引用、模型挂引用、依据类别、历史恢复、严格切换、恶意文档、幂等、一致正文 |
| 链路/故障 | 6 | 解析超时、生成失败、检索故障、预算不足、并发状态竞争、失败后重试 |
| 合计 | 48 | 受控模型与隔离API自动检查 |

真实模型开发验证8组多轮序列，使用公开合成资料：三类基础场景、无附件、澄清恢复、拒答恢复、文档切换、模式切换。
另冻结4组未用于提示词调整的验收序列；一旦用于修正，应改列开发集并另留验收样本。
浏览器实际操作另核对模式切换、无附件问答、候选澄清、来源区块和刷新恢复，接口不替代点击。

目标：
- 标注意图/对象/方面联合正确率>=95%；分母与样本数明确。
- 可回答问题关键点完整正确率>=90%；误拒答率<=5%，同时正确说明真正缺失部分。
- 待澄清接续、当前范围与跨会话隔离、来源区块结构、引用定位、幂等正确率100%。
- 文档事实的已复核原子事实支持率>=95%；严重编造论文参数、伪造文档引用、越范围来源为0。
- 模型知识单独复核正确性，不能靠“已标记模型补充”免除错误责任。
- 文档概述不得引入模型通用背景；模型知识不得被摘要升级为文档事实。
- 195项既有测试实施前重新枚举；受控回归全通过，新旧严格行为明确对照。
- 35题检索基线Recall@4=1.0、MRR@4=0.9310不下降，按同索引配置验证。
- 原40题真实外发授权仍未取得；可做本地严格结构回归，不冒称真实语义回归。
- 逐阶段耗时、调用数、实际usage、缓存状态和取消/故障单列；少于20个成功样本不宣称稳定p95。
- pending、blocked、not_run保持原状态，不能从分母剔除后宣布全通过。

## 6. 实施顺序

1. 契约与策略：API兼容、模式和区块来源。
2. 焦点与LLM解析：事务状态、澄清恢复、旧会话兼容。
3. 增强生成与一次补检索：独立校验器、预算和故障分支。
4. 前端呈现与固定多轮测试：来源区块、模式切换、报告和人工复核。
用户已确认本设计并授权实施。后续实测与待审状态按报告记录，不将结构通过表述为语义通过。
